## Objetivo

Documentar tu presentación en Markdown y comprobar su formato.

<a id="actividad"></a>

## Actividad — Escribir y publicar

1. Copia la [plantilla de ejemplo](../../../templates/github-profile/PROFILE.md)
   a tu README. Sustituye `TU_NOMBRE` y `TU_USUARIO` y adapta la presentación
   y los objetivos a tu situación.
2. Agrega un enlace útil y un comando como código en línea.
3. Previsualiza el documento y corrige cualquier problema de formato.
4. Si eliges GitHub, publícalo en el repositorio público con tu nombre de usuario
   y comprueba que aparece en tu perfil. Sin cuenta, conserva el archivo local.
5. Escribe una instrucción breve para una IA con objetivo, contexto y criterio
   de validación. Explica qué aporta Markdown a su organización.

<details>
<summary>Una pista si no sabes qué escribir</summary>

Empieza con tres elementos: quién eres, qué estás aprendiendo y un objetivo
concreto. Usa un encabezado y una lista; después revisa la vista previa y los
enlaces. No necesitas tarjetas, estadísticas ni automatizaciones.

</details>

## Comprueba tu entrega

| Revisión | Resultado esperado |
| --- | --- |
| Texto propio | No quedan TU_NOMBRE o TU_USUARIO sin sustituir |
| Vista previa | Encabezados, lista, código y enlace se muestran como esperabas |
| Enlace | Puedes abrir y explicar su destino |
| Publicación, si la elegiste | Tu presentación aparece en el perfil correcto |
| Explicación | Distingues Git, GitHub y Markdown sin leer la definición |

En pareja, una persona escribe y explica; la otra revisa vista previa y enlaces.
Cambien de papeles al ajustar la presentación. Una revisión correcta del formato
no sustituye explicar qué hiciste.

## Evidencia y reflexión

- El README se visualiza correctamente y expresa tus objetivos reales.
- Puedes explicar la diferencia entre Git, GitHub y Markdown.
- ¿Qué diferencia hay entre el texto fuente y la vista previa?
- ¿Qué distingue un repositorio de GitHub de un archivo Markdown?
- ¿Qué información cambia al hacer público el repositorio del perfil?
- ¿Por qué Markdown no garantiza que una IA entienda o cumpla una instrucción?

Al terminar, conserva archivo o enlace y tus dudas en tu carpeta personal.
Puedes copiar la [bitácora de 00](../../../templates/learning-session/bitacora-00.md).
PROGRESS.md conserva el estado editorial del curso. No marques el nivel completo
por terminar este lab: aún faltan el script, el entorno y el notebook.
