Propósito

Representar varios datos sin crear una variable distinta para cada uno. Las listas organizan elementos y los diccionarios nombran los campos de un registro; comprender sus referencias permite explicar qué estás modificando.

Antes de empezar

Completa 01.01 — Variables, tipos y operaciones y su lab. Conserva el entorno de Python del módulo 00, sin paquetes externos. Edita en tu editor habitual y ejecuta desde la terminal. Las ventas de ejemplo están definidas en la página y en el script; no necesitas archivos de datos ni ciclos todavía.

Qué vas a aprender

  • Consultar elementos por posición y campos por clave sin confundirlos.
  • Agregar y modificar registros y explicar qué cuenta len en cada estructura.
  • Distinguir una clave ausente de un campo que contiene None.
  • Comparar una referencia compartida, una copia de un registro y una copia superficial de lista.

1. Listas: agrupar elementos en orden

Una lista reúne elementos entre corchetes, separados por comas:

productos = ["cuaderno", "lapiz", "carpeta"]
print(len(productos))  # 3 elementos

La lista conserva un orden y permite repetir elementos. Puede contener valores de distintos tipos, pero conviene mantener un significado consistente para entender tus datos. len(...) cuenta elementos, no suma sus valores.

Acceder a una posición

print(productos[0])   # cuaderno: primera posición
print(productos[1])   # lapiz: segunda posición
print(productos[-1])  # carpeta: última posición

Los índices empiezan en cero. Una lista de tres elementos tiene índices 0, 1 y 2; productos[3] produce IndexError. Una posición no es un identificador permanente: puede cambiar cuando agregas, quitas o reordenas elementos.

Seleccionar un tramo

print(productos[0:2])  # ["cuaderno", "lapiz"]

Este corte, llamado slice, incluye el inicio y excluye el final. Produce otra lista; no elimina elementos de la original.

2. Modificar una lista

# Cambia el elemento de una posición
productos[1] = "lapiz azul"
# Agrega al final
productos.append("rotulador")
# Retira y devuelve el último elemento
retirado = productos.pop()
print(retirado)  # rotulador

append y pop son métodos: operaciones de ese objeto. El punto conecta la lista con el método. append modifica la lista y devuelve None; no escribas productos = productos.append(...), porque perderías el nombre que refería a la lista. Una lista vacía se escribe []; retirar con pop() de una lista vacía falla.

Para comprobar: ¿cuántos elementos quedan después de agregar y retirar el último? Predice antes de ejecutar.

3. Diccionarios: nombrar los campos de un registro

Una venta tiene campos con significados distintos. Un diccionario relaciona claves con valores, usando llaves y pares separados por comas:

venta = {
    "producto": "cuaderno",
    "unidades": 2,
    "precio_unitario_mxn": 40,
}

En este ejemplo las claves son textos. El nombre del campo permite acceder sin recordar una posición:

print(venta["producto"])  # cuaderno
importe_mxn = venta["unidades"] * venta["precio_unitario_mxn"]
print(importe_mxn)  # 80

Una clave es única dentro del diccionario. Asignar de nuevo a esa misma clave reemplaza su valor; no agrega un segundo campo con igual nombre.

Modificar y agregar campos

# Cambia un campo existente
venta["unidades"] = 3
# Agrega un campo nuevo, calculado con las entradas actuales
venta["importe_mxn"] = venta["unidades"] * venta["precio_unitario_mxn"]

El diccionario es mutable: su contenido puede cambiar. Un campo calculado no se actualiza solo si después cambias las unidades; debes recalcularlo, como con las variables de la lección 01.

Consultar una clave que puede faltar

print("region" in venta)            # False: pregunta si existe la clave
print(venta.get("region"))          # None: la clave no existe
print(venta.get("region", "sin dato"))  # Valor alternativo

venta["region"] produciría KeyError en este registro. get permite consultar con un valor alternativo; no agrega el campo ni demuestra que el registro sea válido. Si la clave existe con valor None, get devuelve ese None, no el alternativo. in sobre un diccionario comprueba sus claves; sobre una lista comprueba sus elementos.

len(venta) cuenta campos, no ventas. Un diccionario vacío se escribe {}.

4. Lista de diccionarios: varios registros

ventas = [
    {"producto": "cuaderno", "unidades": 2, "precio_unitario_mxn": 40},
    {"producto": "lapiz", "unidades": 5, "precio_unitario_mxn": 10},
    {"producto": "carpeta", "unidades": 1, "precio_unitario_mxn": 35},
]

La lista contiene tres registros. Cada diccionario describe uno:

print(len(ventas))                    # 3 registros
print(ventas[0]["producto"])          # cuaderno
print(ventas[1]["unidades"])          # 5

Lee ventas[0]["producto"] en dos pasos: elige el primer diccionario y después su campo producto. Los registros mantienen los mismos nombres de campos para poder compararlos. En un CSV esos campos se parecerán a los nombres de columnas.

Con esta estructura todavía no filtramos ni recorremos todos los registros. Lo haremos con condiciones y ciclos en la siguiente lección.

5. Referencias y copias: qué estás modificando

Asignar otro nombre no crea una copia

original = {"producto": "cuaderno", "unidades": 2}
otro_nombre = original
otro_nombre["unidades"] = 4
print(original["unidades"])  # 4: ambos nombres refieren al mismo diccionario

Lo mismo ocurre al asignar una lista a otro nombre. No son dos registros independientes: estás accediendo al mismo objeto mutable.

Copiar un registro sencillo

original = {"producto": "cuaderno", "unidades": 2}
copia = original.copy()
copia["unidades"] = 4
print(original["unidades"])  # 2
print(copia["unidades"])     # 4

copy() crea otro diccionario. Aquí sus valores son texto y enteros, así que modificar el campo de la copia no cambia el original.

Una copia superficial no duplica los registros internos

copia_ventas = ventas.copy()
copia_ventas[0]["unidades"] = 9
print(ventas[0]["unidades"])  # 9

La lista exterior es nueva, pero contiene los mismos diccionarios. Este detalle importa al explorar cambios sin querer alterar los datos originales. Por ahora copia explícitamente el registro sencillo que modificarás; copias profundas se estudiarán cuando haya estructuras más complejas.

Para conversar: ¿qué diferencia hay entre una colección nueva y registros nuevos dentro de esa colección?

Errores que conviene reconocer

Situación Qué revisar

KeyError Nombre exacto de la clave y si está presente
TypeError al calcular Si el campo contiene texto, None o un número

Cambió el original Si compartiste una referencia o hiciste una copia superficial
