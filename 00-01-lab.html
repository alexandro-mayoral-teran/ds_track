Volver a la lección · Actividad · Comprobación

Antes de copiar la plantilla: escribe qué te gustaría que otra persona supiera de ti y qué estás aprendiendo. Después compara esa intención con tu README.

Relación

  • Módulo: 00_getting_started.
  • Lección: Git, GitHub, Markdown y perfil.
  • Proyecto: no aplica todavía; el README constituye la evidencia inicial.

Objetivo

Documentar tu presentación en Markdown y comprobar su formato.

Actividad — Escribir y publicar

  1. Copia la plantilla de ejemplo a tu README. Sustituye TU_NOMBRE y TU_USUARIO y adapta la presentación y los objetivos a tu situación.
  2. Agrega un enlace útil y un comando como código en línea.
  3. Previsualiza el documento y corrige cualquier problema de formato.
  4. Si eliges GitHub, publícalo en el repositorio público con tu nombre de usuario y comprueba que aparece en tu perfil. Sin cuenta, conserva el archivo local.
  5. Elige uno de los otros casos de uso y escribe un ejemplo breve con secciones adecuadas. Si eliges IA, redacta un prompt con objetivo, contexto y comprobación. Basta explicarlo: no necesitas usar una IA ni crear una skill.
Una pista si no sabes qué escribir

Empieza con tres elementos: quién eres, qué estás aprendiendo y un objetivo concreto. Usa un encabezado y una lista; después revisa la vista previa y los enlaces. No necesitas tarjetas, estadísticas ni automatizaciones.

Comprueba tu entrega

Revisión Resultado esperado
Texto propio No quedan TU_NOMBRE o TU_USUARIO sin sustituir
Vista previa Encabezados, lista, código y enlace se muestran como esperabas
Enlace Puedes abrir y explicar su destino
Publicación, si la elegiste Tu presentación aparece en el perfil correcto
Explicación Distingues Git, GitHub y Markdown sin leer la definición

En pareja, una persona escribe y explica; la otra revisa vista previa y enlaces. Cambien de papeles al ajustar la presentación. Una revisión correcta del formato no sustituye explicar qué hiciste.

Evidencia y reflexión

  • El README se visualiza correctamente y expresa tus objetivos reales.
  • Puedes explicar la diferencia entre Git, GitHub y Markdown.
  • ¿Qué diferencia hay entre el texto fuente y la vista previa?
  • ¿Qué distingue un repositorio de GitHub de un archivo Markdown?
  • ¿Qué información cambia al hacer público el repositorio del perfil?
  • ¿Qué problema ayuda a resolver Markdown en el otro caso que elegiste?
  • Si elegiste IA, ¿qué contexto aporta tu prompt y cómo comprobarías la respuesta?

Al terminar, conserva archivo o enlace y tus dudas en tu carpeta personal. Puedes copiar la bitácora de 00. PROGRESS.md conserva el estado editorial del curso. No marques el nivel completo por terminar este lab: aún faltan el script, el entorno y el notebook.
