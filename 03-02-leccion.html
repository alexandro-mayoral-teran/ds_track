Propósito

Expresar preguntas pequeñas con SQL y comprobar qué filas responden a ellas.

Antes de empezar

Completa 03.01 — Modelo relacional y SQLite y su lab. Usa la misma base ficticia de 16 clientes, 24 créditos y 48 cortes; no necesitas instalar paquetes. Una fila de cortes sigue siendo un crédito en una fecha, aunque selecciones solo algunas columnas.

La muestra conserva 16 clientes, 24 créditos y 48 observaciones. Una fila de cortes representa un crédito en una fecha aunque selecciones menos columnas. Agregaciones y joins se desarrollan en 03.04 y 03.05; aquí se consulta sin modificarla.

Qué vas a aprender

  • Seleccionar columnas y usar alias sin cambiar la unidad de registro.
  • Combinar filtros y parámetros con condiciones explícitas.
  • Ordenar con desempate, limitar resultados y explicar DISTINCT.
  • Distinguir NULL, cero y selección vacía y cerrar la conexión.

1. De la pregunta a SELECT y FROM

Pregunta: ¿qué saldos conocemos de las primeras tres observaciones de octubre, ordenadas por identificador?

SELECT id_credito AS credito, saldo_mxn
FROM cortes
WHERE fecha_corte = '2026-10-31'
ORDER BY id_credito
LIMIT 3;

SELECT elige las columnas del resultado; FROM identifica la tabla; WHERE decide qué filas cumplen la condición. AS cambia el nombre de una columna del resultado, no modifica el esquema ni los datos. Las comas separan columnas. El punto y coma termina la sentencia. Escribimos palabras de SQL en mayúsculas por legibilidad. Los textos llevan comillas simples y los números se escriben sin ellas. Los IDs son texto: ‘001’ conserva sus ceros. SELECT * devuelve todas las columnas, pero nombrarlas hace explícito qué necesitas.

credito saldo_mxn
001 1300
002 1400
003 1500 
flowchart LR
    T["FROM: 48 observaciones"] --> F["WHERE: 24 de octubre"]
    F --> C["SELECT: identificador y saldo"]
    C --> O["ORDER BY: identificador"]
    O --> L["LIMIT: primeras 3 filas"]

Es una guía para interpretar el resultado, no una promesa del orden físico de trabajo del motor. En palabras: elegimos octubre, mostramos dos campos, ordenamos y tomamos tres filas. SELECT consulta sin cambiar las tablas.

2. Filtrar y combinar condiciones

SELECT id_credito, saldo_mxn, dias_atraso
FROM cortes
WHERE fecha_corte = '2026-10-31' AND dias_atraso >= 30
ORDER BY dias_atraso DESC, id_credito ASC;

Las comparaciones incluyen =, <>, <, <=, > y >=. AND requiere ambas condiciones; OR acepta al menos una; NOT niega una condición. Usa paréntesis para expresar la intención: AND tiene prioridad sobre OR.

SELECT id_credito, fecha_corte, dias_atraso
FROM cortes
WHERE fecha_corte = '2026-10-31'
  AND (dias_atraso = 0 OR dias_atraso >= 30)
ORDER BY id_credito;

Sin esos paréntesis, la condición fecha_corte = '2026-10-31' AND dias_atraso = 0 OR dias_atraso >= 30 también acepta atrasos de septiembre. La versión agrupada devuelve 13 filas de octubre. El filtro >= 30 devuelve nueve: 004, 009, 014, 019 (con 40 días), luego 003, 008, 013, 018, 023 (con 30 días).

3. Orden, empates y LIMIT

ASC ordena ascendente y es el valor predeterminado; DESC, descendente. Una segunda columna desempata. Al consultar varios cortes usa ORDER BY fecha_corte, id_credito: el identificador solo no distingue sus dos fechas. Sin ORDER BY el orden no está garantizado, aunque parezca estable. LIMIT 3 restringe a tres filas; no toma una muestra aleatoria ni significa los tres mayores sin ordenar por la medida.

Las fechas YYYY-MM-DD validadas de esta base pueden ordenarse como texto en orden cronológico. Esa propiedad no se traslada a fechas como 31/10/2026.

4. NULL, cero y lógica con valores ausentes

SELECT id_credito
FROM cortes
WHERE fecha_corte = '2026-10-31' AND saldo_mxn IS NULL
ORDER BY id_credito;

Devuelve 022, 023 y 024. saldo_mxn = 0 devuelve solo 004. Para conocidos utiliza IS NOT NULL. No uses = NULL ni <> NULL: una comparación ordinaria con NULL produce desconocido. WHERE conserva solo las condiciones verdaderas, por lo que dias_atraso >= 30 y NOT (dias_atraso >= 30) excluyen ambos los atrasos ausentes.

Si la pregunta incluye atrasados o desconocidos, exprésala:

SELECT id_credito, dias_atraso
FROM cortes
WHERE fecha_corte = '2026-10-31'
  AND (dias_atraso >= 30 OR dias_atraso IS NULL)
ORDER BY id_credito;

Devuelve 12 filas, incluyendo 006, 012 y 024 con atraso desconocido. No significa que esas tres estén atrasadas. sqlite3 entrega NULL como None de Python; pandas usa representaciones como NA/NaN según el tipo. Recupera la idea de faltantes y máscaras en 02.03, pero escribe la condición SQL de forma explícita.

5. DISTINCT cambia qué representa el resultado

SELECT DISTINCT fecha_corte
FROM cortes
ORDER BY fecha_corte;

Devuelve dos filas: 2026-09-30 y 2026-10-31. DISTINCT elimina repeticiones de la combinación completa de columnas seleccionadas. Si añades id_credito obtienes 48 pares distintos. Ya no estás mostrando observaciones completas cuando seleccionas solo fechas distintas. No uses DISTINCT para ocultar problemas de claves o joins.

6. Ejecutar desde Python y cerrar la conexión

first_queries.py abre exclusivamente una base existente en solo lectura, ejecuta seis consultas y cierra en finally incluso si hay errores. No prepara ni reinicia la base. Puedes leer y adaptar una consulta del script:

sql = "SELECT id_credito FROM cortes WHERE fecha_corte = ? ORDER BY id_credito"
cursor = conexion.execute(sql, ("2026-10-31",))
filas = cursor.fetchall()

execute envía una sentencia y sus parámetros; fetchall recupera las filas como lista de tuplas. Una lista vacía es un resultado válido. El ? ocupa el lugar de un valor; no lo pongas entre comillas. La coma en (valor,) crea una tupla de un elemento. No construyas SQL interpolando valores con f-strings. Los parámetros no sustituyen nombres de tablas o columnas. En el script, cursor.description permite recuperar los nombres de columnas, incluido el alias credito. El bloque with de una Connection controla transacciones; no sustituye close.
