A. Función o resultado — base

Desde 01_notebook_to_modules, inicia python y prepara:

from analisis_cartera.contratos import coverage_pct

def evaluate(operation, known, total):
    return operation(known, total)

operation = coverage_pct
result = coverage_pct(2, 3)
  1. Predice el tipo de operation y result; después consulta type.
  2. Ejecuta evaluate(operation, 0, 3) y evaluate(operation, 0, 0).
  3. Explica qué fallaría al pasar result en lugar de operation.
  4. Describe quién llama a len en el ejemplo sorted de la lección.

Comprobación: identificas dónde se guarda una función y dónde se ejecuta. Evidencia: tabla breve con expresión, objeto recibido y resultado esperado.

Ver solución razonada de A

operation es una función; result es float. Las llamadas producen 0.0 y None. Si evaluate recibe result, intenta llamar un número y aparece TypeError. sorted recibe len como función y la llama para obtener claves de orden; no le entregamos el resultado de len().

Ver solución razonada de B

C. Argumentos, identidad y metadatos — práctica

En una nueva sesión python desde el mismo directorio:

import inspect
from analisis_cartera.instrumentacion import log_call

def keep(items, *, marker=None):
    """Devolver el mismo objeto recibido, sin copiarlo."""
    return items

observed = log_call(keep)
items = []
returned = observed(items, marker=0)
print(returned is items)
print(observed.__name__)
print(observed.__doc__)
print(observed.__wrapped__ is keep)
print(inspect.signature(observed))
print(inspect.signature(observed, follow_wrapped=False))
  1. Explica por qué la prueba de identidad es más precisa que == para este contrato.
  2. Identifica cómo se recogieron/reexpidieron marker y la lista.
  3. Relaciona la firma visible con wrapped y la firma sin seguimiento con *args/**kwargs. ¿Impone wraps las condiciones del docstring?
  4. Explica por qué puedes no ver mensajes INFO en esa sesión, aunque la función se ejecute.

Comprobación: misma lista, nombre/documentación conservados y enlace original. Evidencia: resultados y explicación de lo que wraps aporta y no aporta.

Ver solución razonada de C

La identidad es True: no se devuelve otra lista simplemente igual. args recoge items y kwargs recoge marker=0; la llamada con asteriscos los reenvía. wraps conserva el nombre keep y su docstring, y enlaza la función original. inspect.signature muestra (items, *, marker=None); sin seguir el enlace muestra los parámetros variables. El docstring sigue siendo documentación, no validación. El logger no configura la consola al importarse y el nivel puede ocultar INFO.

Un iterador retornado sigue sin consumirse; ese Fin solo afirma que la función normal devolvió su objeto.

Comprobación: misma excepción y un solo efecto; ningún reintento añadido por la instrumentación. Evidencia: método, ejecución y razón de cada esperado.

Ver una solución razonada de E

Dentro de la clase existente:

    def test_falla_no_repite_efecto(self):
        calls = []
        error = ValueError("Falla prevista")

        @log_call
        def operation():
            calls.append("efecto")
            raise error

        with self.assertLogs(LOGGER_NAME, level="INFO") as captured:
            with self.assertRaises(ValueError) as caught:
                operation()
        self.assertEqual(calls, ["efecto"])
        self.assertIs(caught.exception, error)
        self.assertEqual([r.getMessage() for r in captured.records],
                         ["Inicio: operation", "Falla: operation"])

LOGGER_NAME y log_call ya están disponibles en el archivo. La marca es un efecto pequeño y local que permite detectar una repetición sin escribir entregas. assertLogs captura los mensajes temporalmente y los consulta mediante records. No se garantiza repetibilidad de una operación solo por envolverla: reintentos requieren otro contrato, especialmente ante escrituras.
