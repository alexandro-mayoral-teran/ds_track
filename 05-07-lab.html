A. Predecir qué queda por consumir — base

values = [10, 20, 30]
walk = iter(values)
alias = walk

Predice y después ejecuta, en este orden:

  1. next(alias).
  2. list(walk).
  3. list(alias).
  4. list(iter(values)).
  5. iter(walk) is walk.

Ejecuta además el ejemplo squares de la lección y explica cuándo aparece el mensaje que está dentro del cuerpo. No confundas crear otro generador con reiniciar el anterior.

Comprobación: puedes dibujar la posición después de cada consumo. Evidencia: tabla de predicción/resultado y explicación de alias.

Ver solución razonada de A

Resultados: 10; [20, 30]; []; [10, 20, 30]; True. alias y walk comparten el avance. La lista sigue disponible y permite otro iterador. En squares el mensaje interno aparece al primer next, después de “Generador creado”; después de entregar 4 y 9, ese generador queda agotado.

B. Último lote y errores diferidos — base

Importa iter_batches en la misma sesión:

from analisis_cartera.iteracion import iter_batches

walk = iter_batches([1, 2, 3, 4, 5], 2)
print(next(walk))
print(list(walk))
print(list(walk))
  1. Predice y comprueba los tres resultados.
  2. Repite con fuente vacía y con tamaño 20 sobre cinco valores.
  3. Crea invalid = iter_batches([1], 0). Identifica en qué llamada aparece ValueError y dónde tendría que estar try/except.
  4. Explica qué ocurriría si solo se entregaran lotes de tamaño exactamente 2.
  5. Sal con exit() y sigue el recorrido de tu shell en la lección para ejecutar script, colección nueva y colección combinada. Conserva las cantidades/códigos.

Comprobación: mantienes [5], distingues fin normal de error y no reinicias accidentalmente el recorrido. Original: 15 métodos nuevos y 61 combinados. Evidencia: resultados, comandos, intérprete y códigos de salida.

Ver solución razonada de B

Se imprime [1, 2], luego [[3, 4], [5]] y finalmente []. La fuente vacía no entrega lotes; tamaño 20 entrega una lista con los cinco elementos. La validación de cero ocurre al consumir invalid, por ejemplo con next, no al crearlo. Exigir lotes completos descartaría [5] y rompería conteos y resultados. El código de salida de script/pruebas correctos es 0; no basta obtener OK con cero pruebas descubiertas. Los ejercicios propios aumentan los métodos contados.

Ejecuta el ejemplo con path, DictReader y salida temprana de la lección.

  1. Explica por qué handle.closed es False tras break dentro de with.
  2. Comprueba que es True al salir del bloque.
  3. Identifica qué objeto posee el archivo: reader, iter_batches o el llamador.

Comprobación: el consumo se realiza mientras el recurso está abierto; el cierre no depende de agotar el generador. Evidencia: secuencia de estados y responsable del cierre.

Ver solución razonada de C

break termina el ciclo, pero el with exterior continúa activo. El llamador abrió el archivo y su bloque lo cierra al salir. Reader y generador consumen esa fuente; iter_batches no promete cerrarla. Devolver un lector cuyo with ya terminó deja pendiente un consumo sobre un archivo cerrado. Una excepción también debe salir por el with para liberar el recurso.

D. Conciliar y explicar la memoria — práctica

Desde 01_notebook_to_modules, inicia python y prepara:

from pathlib import Path
from pandas.testing import assert_frame_equal
from analisis_cartera.flujo import build_analysis
from analisis_cartera.iteracion import batch_indicators

source = Path("../../03_sql_databases/01_relational_sqlite/data")
expected = build_analysis(source, "2026-10-31")["indicadores"]
for size in [1, 7, 100]:
    actual = batch_indicators(source, "2026-10-31", batch_size=size)
    assert_frame_equal(actual, expected, check_exact=True)
print(actual)
  1. Verifica Todos: 24/21, mediana 2300 MXN y cobertura 87,5 %.
  2. Explica por qué educación conserva tres registros sin mediana y con cobertura 0.
  3. Calcula el error de promediar medianas de los lotes [0, 0] y [100].
  4. Identifica qué guardan groups, seen, values y all_values dentro de la función. ¿Qué cambia al reducir batch_size y qué estructuras siguen creciendo?
  5. Lee test_duplicado_entre_lotes_y_fuera_del_corte. Explica qué se perdería reiniciando seen en cada lote o filtrando antes de validar.

Comprobación: tablas equivalentes para todos los tamaños y límite de memoria explicado sin prometer mejoras de tiempo o memoria no medidas. Evidencia: conciliación, cuenta manual e inventario de objetos vivos.

Ver solución razonada de D

Los valores originales coinciden con el recorrido completo. Educación tiene base 3 y ningún conocido; su cobertura es 0, pero no hay mediana. El promedio de medianas 0 y 100 sería 50; la mediana de [0, 0, 100] es 0. groups retiene el catálogo; seen todas las claves; values los saldos conocidos del corte; all_values reúne referencias para la mediana global. Reducir el lote no elimina esas estructuras ni los ordenamientos temporales. Un duplicado fuera del corte también invalida el archivo. seen debe atravesar los lotes; el filtro no debe ocultar ese problema.
