Propósito

Aprender a ubicarse dentro de un proyecto y comprobar qué herramientas están disponibles. Usaremos PowerShell en Windows y mostraremos el equivalente en un shell Unix, como Bash o Zsh. El objetivo no es memorizar dos listas de comandos, sino reconocer las operaciones comunes.

Antes de empezar

Retoma 00.01 — Markdown y perfil. Necesitas una copia descargada o clonada de DS Track y acceso a una terminal. Elige PowerShell o Bash/Zsh; no necesitas completar los dos recorridos.

Comienza identificando la carpeta raíz del proyecto. Las comprobaciones de versiones permiten detectar herramientas disponibles o faltantes: registra lo que falta para preparar el entorno en 00.05. El verificador requiere Python; si aún no está disponible, conserva esa comprobación pendiente.

Si quieres probar sin instalar Python localmente, puedes empezar con el notebook para Colab. Prepara su propia carpeta de ejemplo y permite ensayar Bash. La copia real del proyecto y la comprobación de tu entorno personal se retoman después; el notebook no las acredita.

Qué vas a aprender

  • Identificar el directorio actual y distinguir rutas absolutas y relativas.
  • Localizar archivos e inspeccionar un CSV con tu shell, reconociendo equivalencias con el otro recorrido.
  • Distinguir shell de programa y consultar las versiones de las herramientas disponibles.
  • Registrar herramientas disponibles y pendientes; si tienes Python, ejecutar el verificador e interpretar su resultado.
  • Explicar qué información permite repetir una secuencia de comandos y comprobarla.

Por qué aprender a trabajar en terminal

La terminal permite indicar acciones mediante comandos: abrir una carpeta, localizar archivos, ejecutar un programa o comprobar qué versión está instalada. Estos pasos pueden escribirse, compartirse y repetirse. Cuando alguien te entregue un análisis, podrás seguir sus instrucciones y comprobar cómo se obtuvo el resultado.

No necesitas dejar de usar el explorador o un editor. La terminal los complementa: el explorador ayuda a ver archivos, el editor a modificarlos y la terminal a ejecutar acciones concretas sobre ellos.

Este ejemplo muestra una posibilidad; el script todavía no existe y no debes ejecutarlo. Primero aprenderás a ubicarte, leer rutas y reconocer un comando.

Antes de comenzar: cuatro conceptos diferentes

Concepto Ejemplo Función
Sistema operativo Windows, Linux, macOS Administra el equipo
Terminal Windows Terminal, una consola SSH Muestra y recibe texto
Shell PowerShell, Bash, Zsh Interpreta los comandos
Programa Git, Python, uv Realiza una tarea específica

PowerShell y Bash no son sistemas operativos ni terminales: son shells. Una terminal puede ejecutar distintos shells. En servidores y contenedores es común encontrar Linux con Bash o un shell compatible.

Los comandos propios del shell pueden cambiar. Los comandos de programas externos suelen conservarse:

git status
python --version
uv run python archivo.py

Por eso git status es esencialmente igual desde PowerShell o Bash, mientras que comprobar si un archivo existe utiliza sintaxis diferente.

Cómo leer un comando

En python --version, python es el programa y --version es una opción que pide mostrar su versión. En Test-Path README.md, Test-Path es el comando de PowerShell y README.md es el argumento que indica qué ruta comprobar.

Las opciones pertenecen a cada herramienta: no todas aceptan las mismas. El comando devuelve una salida o un error; leer ambos forma parte del trabajo. Un bloque Markdown solo muestra el comando: debes ejecutarlo en la terminal.

1. El directorio actual

La terminal siempre está situada en una carpeta. Los comandos que usan rutas relativas parten de esa ubicación.

Get-Location

La ruta depende de dónde descargaste el proyecto. Por ejemplo:

C:\aprendizaje\ds_track

No copies esta ruta como si existiera en tu computadora: comprueba la tuya. La raíz del proyecto contiene README.md, ROADMAP.md y pyproject.toml.

2. Ver el contenido

Get-ChildItem

Su alias corto es ls, pero durante esta primera lección usaremos el nombre completo para hacer explícita la operación.

Para mostrar también elementos ocultos, como .gitignore:

Get-ChildItem -Force

PowerShell trabaja principalmente con objetos; los shells Unix tradicionalmente componen herramientas que intercambian texto. Esta diferencia será importante cuando estudiemos pipes, pero no necesitamos profundizar todavía.

3. Rutas absolutas y relativas

Una ruta absoluta parte desde una unidad:

C:\aprendizaje\ds_track\README.md

Una ruta relativa parte desde el directorio actual:

README.md
curriculum\00_getting_started\README.md

Git y muchas herramientas aceptan / también en Windows. En código Python preferiremos pathlib para construir rutas sin asumir un sistema operativo.

Si una ruta contiene espacios, escríbela entre comillas. Ejemplo ilustrativo:

Test-Path "C:\Mis proyectos\ds_track\README.md"

Podemos preguntar si ambas existen:

Test-Path README.md
Test-Path curriculum\00_getting_started\README.md

Ambas instrucciones deben devolver True cuando se ejecutan desde la raíz del proyecto.

4. Cambiar de carpeta

# Entra al módulo desde la raíz de ds_track
Set-Location curriculum\00_getting_started

# Confirma la nueva ubicación
Get-Location

# Lista los archivos de esta carpeta
Get-ChildItem

# Sube dos niveles para volver a la raíz
Set-Location ..\..

# Comprueba que regresaste a ds_track
Get-Location

PowerShell también reconoce cd como alias de Set-Location.

.. significa “carpeta padre” y . significa “carpeta actual”.

Antes de ejecutar un archivo, vuelve a comprobar tu ubicación con Get-Location. Muchos errores de archivo no encontrado son, en realidad, errores de ubicación.

7. Primer contacto con un archivo de datos

Parte del núcleo: puedes llegar aquí directamente desde el paso 4.

Incluimos ventas_demo.csv, una muestra ficticia de tres ventas. Un CSV es un archivo de texto que representa una tabla; en este ejemplo las columnas están separadas por comas y la primera línea contiene sus nombres.

Desde la raíz del proyecto, localízalo y lee las primeras tres líneas:

# Busca archivos CSV en la carpeta de la lección
Get-ChildItem curriculum\00_getting_started\02_terminal_paths -Filter *.csv

# Confirma que existe el archivo de muestra
Test-Path curriculum\00_getting_started\02_terminal_paths\ventas_demo.csv

# Lee el encabezado y los primeros dos registros
Get-Content curriculum\00_getting_started\02_terminal_paths\ventas_demo.csv -TotalCount 3

*.csv busca nombres con esa extensión. -TotalCount 3 muestra solo tres líneas, útil para inspeccionar el comienzo sin imprimir todo el archivo.

Resultado esperado de la lectura:

fecha,producto,unidades,importe_mxn
2026-01-01,cuaderno,2,80
2026-01-02,lapiz,5,50

Observa que tres líneas incluyen el encabezado y dos registros. Mostrar el texto no valida tipos, fechas ni importes y, en otros CSV, un registro puede ocupar varias líneas. La limpieza y el análisis se estudiarán con Python y pandas.

Para comprobar: identifica los nombres de las columnas. Si cambias de carpeta, ¿por qué la misma ruta relativa podría dejar de funcionar?

8. Extensión opcional: explorar el CSV desde la terminal

Esta sección es opcional. Muestra lo que puedes hacer al combinar comandos; no necesitas memorizar su sintaxis para continuar a la lección 03. Trabajaremos con el mismo archivo, sin modificarlo.

De texto a registros

Desde la raíz de ds_track, guarda la ruta en una variable para no repetirla:

$ventasPath = "curriculum\00_getting_started\02_terminal_paths\ventas_demo.csv"

Una variable conserva un valor que puedes usar en otros comandos. Aquí guarda la ruta, no el contenido del archivo.

Contar líneas de texto:

Get-Content $ventasPath | Measure-Object -Line

Verás Lines: 4: el encabezado y tres líneas de datos. El símbolo |, llamado pipe, pasa la salida del comando de la izquierda al de la derecha. Measure-Object mide lo que recibe.

Leer registros del CSV:

# Interpreta el CSV y reúne sus registros en una colección
$ventas = @(Import-Csv $ventasPath)

# Muestra los registros importados
$ventas

# Cuenta los registros sin incluir el encabezado
$ventas.Count

Import-Csv interpreta el encabezado como nombres de columnas. Cada registro se convierte en un objeto con propiedades como producto e importe_mxn. @(...) reúne los resultados en una colección; su propiedad Count devuelve 3. El encabezado ya no cuenta como un registro.

Filtrar por producto:

$ventas | Where-Object { $_.producto -eq "lapiz" }

Where-Object conserva los registros que cumplen la condición. Dentro de las llaves, $_ representa el registro que se está revisando y -eq significa «igual a». El resultado es la venta de cinco lápices por 50 MXN.

Filtrar por importe y elegir columnas:

$ventas |
    Where-Object { [decimal]$_.importe_mxn -ge 50 } |
    Select-Object producto, importe_mxn

Import-Csv devuelve los campos como texto. [decimal] convierte el importe a número para compararlo; -ge significa «mayor o igual que». Select-Object elige las columnas que quieres mostrar. Verás cuaderno y lapiz, con importes de 80 y 50. La conversión supone importes válidos con el formato sencillo de esta muestra.

Contar las ventas filtradas y sumar importes:

# Filtra los importes y cuenta los registros que cumplen: 2
($ventas | Where-Object { [decimal]$_.importe_mxn -ge 50 } | Measure-Object).Count

# Convierte cada importe a número y suma todas las ventas: 165
($ventas | ForEach-Object { [decimal]$_.importe_mxn } | Measure-Object -Sum).Sum

Obtendrás 2 ventas con importe de al menos 50 MXN y 165 MXN de importe total. ForEach-Object transforma cada registro en su importe numérico antes de sumar. Aquí importe_mxn representa el total de cada venta, no el precio por unidad; no debes multiplicarlo de nuevo por unidades.

Qué demuestra esta práctica

Puedes encadenar acciones pequeñas: leer → filtrar → seleccionar → resumir. Ese mismo patrón aparecerá después en pandas y SQL. La terminal te permite explorar rápidamente; elegir una herramienta adecuada y verificar el resultado sigue siendo parte del análisis.

Reto opcional: filtra las ventas con al menos dos unidades. ¿Cuántos registros quedan? Antes de ejecutar, predice la respuesta leyendo la muestra.

Ver resultado y explicación del reto — PowerShell

Desde la raíz del proyecto, una forma de comprobarlo es:

$ventasReto = @(Import-Csv "curriculum\00_getting_started\02_terminal_paths\ventas_demo.csv")
$seleccionReto = @($ventasReto | Where-Object { [int]$_.unidades -ge 2 })
$seleccionReto | Select-Object producto, unidades
$seleccionReto.Count

Resultado: quedan 2 registros:

Producto Unidades
cuaderno 2
lapiz 5

[int] convierte las unidades de texto a número en esta muestra válida y -ge 2 incluye el límite: dos unidades también cumplen. La venta de carpeta tiene una unidad y queda fuera. @(...) reúne los registros seleccionados y Count los cuenta; no suma unidades. Contrasta estas filas con el CSV original.

Recorrido en Bash/Zsh

Sigue este apartado si usas Bash o Zsh. Parte de la raíz de ds_track y ejecuta un comando a la vez. Las líneas con # explican cada paso.

Abrir la terminal y situarte en el proyecto

  1. Localiza tu copia extraída de DS Track en el administrador de archivos. Busca la carpeta que contiene juntos README.md, ROADMAP.md y pyproject.toml; puede llamarse ds_track-main.

  2. Abre la aplicación Terminal de tu sistema y utiliza una sesión Bash o Zsh. La terminal puede comenzar en tu carpeta personal, no en el proyecto.

  3. Escribe cd, un espacio y la ruta absoluta real de la carpeta entre comillas. Pulsa Enter. Ejemplo ilustrativo para una copia en Linux:

    cd "/home/ana/Mis proyectos/ds_track-main"

8. Extensión opcional: filtrar y resumir

En un shell Unix puedes combinar herramientas de texto. Desde la raíz:

ventas_path="curriculum/00_getting_started/02_terminal_paths/ventas_demo.csv"
# Cuenta saltos de línea, incluido el encabezado: 4
wc -l < "$ventas_path"
# Busca la línea de la venta de lápices
grep ',lapiz,' "$ventas_path"
# Omite el encabezado y muestra producto e importe para ventas de al menos 50
awk -F',' 'NR > 1 && $4 >= 50 { print $2, $4 }' "$ventas_path"
# Suma los importes de los registros: 165
awk -F',' 'NR > 1 { total += $4 } END { print total }' "$ventas_path"
  • wc -l cuenta los saltos de línea: 4 en el archivo incluido.
  • grep encuentra la línea que contiene ,lapiz,.
  • awk -F',' separa por comas; NR > 1 omite el encabezado, $2 es producto y $4 es importe. Los últimos comandos muestran las dos ventas de al menos 50 MXN y el total 165.

Estos comandos de texto funcionan para esta muestra sencilla. grep busca texto, no interpreta columnas, y separar por comas con awk no es un lector general de CSV: campos entre comillas pueden contener comas o saltos de línea. Para esos casos necesitas un lector de CSV, como los que estudiarás en Python. Además, wc -l puede dar un resultado distinto si falta el salto de línea final.

Reto opcional: filtra las ventas con al menos dos unidades. ¿Cuántos registros quedan? Antes de ejecutar, predice la respuesta leyendo la muestra.

Ver resultado y explicación del reto — Bash/Zsh

Desde la raíz del proyecto, una forma de comprobarlo es:

ventas_path="curriculum/00_getting_started/02_terminal_paths/ventas_demo.csv"
awk -F',' 'NR > 1 && $3 >= 2 { print $2, $3; cantidad++ } END { print "Registros:", cantidad+0 }' "$ventas_path"

Resultado:

cuaderno 2
lapiz 5
Registros: 2

NR > 1 omite el encabezado, $3 >= 2 compara las unidades e incluye el límite de dos. print $2, $3 muestra producto y unidades; cantidad++ cuenta cada registro seleccionado. END imprime el conteo final y cantidad+0 daría cero si ninguno cumpliera. La venta de carpeta queda fuera por tener una unidad. Contamos ventas, no sumamos unidades. Contrasta las filas con el CSV original; este uso de awk sigue limitado a la muestra sencilla de la lección.

Para profundizar más adelante: se incorporará una sección de terminal avanzada para estudiar con más detalle filtros, pipes, redirecciones, herramientas como grep y awk, y automatización de tareas con datos. Estos ejemplos son una primera exploración; no necesitas dominar toda su sintaxis para continuar con el recorrido.

Un vínculo con las macros: ejecutar y programar tareas

Si ya usas macros de Excel, conoces la idea de guardar instrucciones para repetir un trabajo. Las macros en VBA se ejecutan dentro de aplicaciones de escritorio como Excel. Un archivo .vbs contiene VBScript, otro lenguaje: no basta renombrar una macro para convertirla. En Windows, si ese componente está disponible, un programa como cscript puede ejecutar el archivo desde la línea de comandos.

Un ejemplo cercano con Excel: en Windows con Excel de escritorio instalado, un script externo puede controlar Excel, abrir un libro .xlsm y llamar una macro existente pasándole argumentos. Por ejemplo:

  1. Abrir un libro ficticio reporte.xlsm.
  2. Llamar su macro GenerarReporte con dos datos: fecha de corte y ruta del CSV.
  3. Revisar el resultado y guardar la salida prevista.
  4. Cerrar el libro y la instancia de Excel que creó el script, incluso si falla.

Excel ofrece Workbooks.Open para abrir el libro y Application.Run para llamar la macro con argumentos por posición. La macro debe estar preparada para recibirlos y su ejecución debe estar permitida por la configuración del entorno. El script coordina; Excel ejecuta el código VBA. Es una posibilidad de automatización, no un programa listo para ejecutar en esta lección.

Por ejemplo, un script podría recorrer una carpeta de entregas diarias, comprobar qué CSV llegaron y escribir una bitácora con archivos faltantes. El Programador de tareas de Windows permite iniciar programas o scripts cada día o a intervalos, como cada hora. El script define qué hacer; la tarea programada define cuándo ejecutarlo. Para repetirlo correctamente hay que indicar el programa, las rutas, la cuenta que lo ejecutará y cómo revisar su resultado.

En el caso de Excel, una tarea que se ejecuta sin sesión interactiva requiere otro diseño: Microsoft no recomienda ni admite la automatización de Office en contextos desatendidos. Por eso conviene distinguir probar el flujo con una persona presente de garantizar que funcione de forma autónoma cada noche.

Contexto actual: Microsoft ha declarado VBScript en desuso y previsto su retirada. Sirve reconocerlo si ya existe en tu trabajo; para nuevas automatizaciones puedes valorar PowerShell o Python según el entorno. Programar una ejecución no depende de usar .vbs. Aquí solo presentamos la posibilidad: no necesitas crear scripts ni tareas programadas en tu equipo para completar la lección.

Otra puerta: buscar patrones con expresiones regulares

Una expresión regular, o regex, describe un patrón de texto para buscar coincidencias. Sirve, por ejemplo, para localizar ciertos mensajes de error, extraer identificadores o revisar si un texto tiene una forma esperada. Esa comprobación de forma no demuestra que el dato sea correcto.

Imagina estas dos líneas de un log ficticio:

ERROR: no se encontró el archivo
INFO: se guardó el mensaje ERROR anterior

Al revisar cada línea, el patrón ^ERROR coincide con la primera y no con la segunda: ^ indica el comienzo y ERROR el texto que debe aparecer allí. La introducción de Microsoft a regex explica estos patrones. No necesitas aprender su sintaxis ahora. El *.csv que ya usaste busca nombres mediante un comodín; no es la misma sintaxis que una regex.

Ejemplos cercanos: RFC, CURP, folios y claves

Caso Qué puede aportar una regex Qué requiere otra comprobación
RFC: Registro Federal de Contribuyentes Detectar longitudes o posiciones de caracteres que no cumplen el formato esperado: 12 caracteres para persona moral y 13 para persona física La forma no confirma su inscripción; el SAT ofrece una validación contra el padrón
CURP: Clave Única de Registro de Población Revisar parte de la estructura de 18 caracteres descrita en el instructivo de SEGOB Las fechas, catálogos y dígito verificador requieren reglas adicionales; coincidir con un patrón no confirma asignación ni identidad
Folios o claves internas Seleccionar claves con cierto prefijo y forma, o extraerlas de mensajes Comprobar que existen, no están duplicadas y corresponden al expediente correcto

Por ejemplo, para folios ficticios con forma CR-2026-0042, el patrón ^CR-[0-9]{4}-[0-9]{4}$ pide CR-, cuatro dígitos, otro guion y cuatro dígitos, de principio a fin. CR-2026-0042 cumple; CR-26-0042 no. Es una regla propia de este ejemplo, no un validador de RFC o CURP; tampoco confirma que el año o el folio existan en un sistema.

En archivos grandes, buscar patrones puede reducir el texto que necesitas inspeccionar sin abrirlo completo en un editor. El tiempo depende del archivo, el patrón y la herramienta: no toda regex será rápida. Si el dato está dentro de un CSV, interpreta primero sus campos con un lector adecuado; buscar texto en una línea no garantiza que encontraste la columna correcta. Antes de usar un patrón en un lote, contrasta ejemplos que deben coincidir y otros que no.

Para imaginar: si recibieras cien archivos, ¿qué revisión pequeña querrías repetir en todos y cómo comprobarías que el resultado es correcto? Estos casos son una invitación para explorar después; no necesitas instalar herramientas científicas ni resolver regex para continuar a 00.03.
