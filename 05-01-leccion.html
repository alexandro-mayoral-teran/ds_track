Propósito

Reutilizar un análisis sin copiar sus funciones entre celdas y scripts. Vamos a separar lectura, transformación, comprobación y presentación en archivos que puedas importar, y a ejecutar el mismo recorrido desde un script y un notebook. La reorganización debe conservar los resultados conocidos.

Antes de empezar

Completa 04.09 — Cierre visual del análisis y su lab, con los prerrequisitos de pandas/SQL. Recupera funciones y mutabilidad de 01.04, notebooks de 00.06 y entorno y dependencias de 00.05. Puedes dividir esta sección en tres sesiones: módulo pequeño, paquete del análisis y reutilización/comprobación. No necesitas dominar clases ni decoradores.

La ejecución inicial usa los CSV sintéticos incluidos en SQL 03.01; no requiere una entrega personal de 04.09. Si la conservas, podrás compararla sobre las mismas fuentes y fecha. La tabla de comprobación de esta lección también ofrece los resultados esperados para reconstruir esa comparación.

Esencial: módulos, importaciones, paquetes regulares, responsabilidades y entrada protegida. Práctica: mismo análisis en script y notebook. Extensión: diagnosticar búsqueda de módulos y caché de importaciones. Argumentos de terminal, logging y configuración se desarrollarán en 05.02; pruebas formales, en 05.04. No agregamos dependencias al proyecto.

Qué vas a aprender

  • Explicar la diferencia entre archivo, módulo, paquete y script.
  • Importar una función y reconocer de qué archivo proviene.
  • Separar el cálculo de las acciones de lectura, dibujo y escritura.
  • Ejecutar una entrada explícita sin exportar al importar el paquete.
  • Usar las mismas funciones en notebook/script sin modificar sys.path.
  • Conciliar registros, medianas, cobertura y ausencias con 04.09.

1. Por qué reorganizar un análisis que ya funciona

Un notebook reúne explicación, exploración y resultados. Eso ayuda a investigar: puedes mirar una tabla, cambiar un filtro y comparar una figura. Sin embargo, copiar una función a otro notebook produce dos versiones que pueden divergir. Si corriges una regla en una copia, la otra conserva el error.

Además, una celda puede utilizar una variable creada mucho antes. Si no sabes qué entrada necesita el cálculo, será difícil ejecutarlo fuera de ese kernel. Extraer una función exige expresar esa entrada mediante argumentos y devolver su resultado. El notebook queda como lector y explorador de esas funciones.

En 04.09 ya usamos un script. El título describe también la transición desde el notebook de pandas 02.10: ambos formatos se benefician de un cálculo compartido. No convertiremos toda celda en módulo ni toda función en un archivo. Agruparemos tareas que cambian por la misma razón y describiremos sus dependencias.

Por ejemplo, cambiar la ubicación de los CSV afecta la lectura; cambiar un color afecta la presentación. Ninguna de esas decisiones debe cambiar la mediana. Esa separación permite revisar una responsabilidad a la vez.

2. Un archivo que podemos ejecutar e importar

Un módulo proporciona nombres que otro código puede utilizar. En este primer caso es un archivo .py: medidas_demo.py. Un script es un archivo que elegimos ejecutar como programa. El mismo archivo puede cumplir ambos papeles; no son dos extensiones distintas.

Primero lee el ejemplo reducido:

from statistics import median

def resumir_saldos(saldos):
    conocidos = [saldo for saldo in saldos if saldo is not None]
    n, k = len(saldos), len(conocidos)
    return {
        "registros": n,
        "conocidos": k,
        "mediana_mxn": median(conocidos) if k else None,
        "cobertura_pct": 100 * k / n if n else None,
    }

La lista por comprensión crea una lista nueva con valores conocidos; is not None conserva el cero. n, k = ... asigna dos cantidades. Cada expresión valor if condición else alternativa selecciona un resultado sin llamar a median ni dividir cuando falta una base. Son las mismas reglas de ausencia y base de 04.09, representadas aquí con listas y None, no con tipos pandas. La entrada debe ser una lista de números no negativos o None de este ejemplo; esta función mínima no es un validador general de datos.

Desde Python o una celda, con la carpeta de la lección como directorio de trabajo, prueba:

import medidas_demo

resultado = medidas_demo.resumir_saldos([0, 100, None, 300])
print(resultado)

Resultado: 4 registros, 3 conocidos, mediana 100 y cobertura 75 %. La función retorna un diccionario; quien llama decide si imprimirlo. import medidas_demo incorpora el nombre del módulo a tu sesión. El punto permite acceder al nombre resumir_saldos que vive dentro del módulo.

Cada módulo tiene su espacio de nombres: los nombres definidos allí. La variable local conocidos vive dentro de la llamada y no aparece como variable de tu notebook. Esto ayuda a evitar dependencias de celdas anteriores.

También puedes seleccionar un nombre:

from medidas_demo import resumir_saldos
resultado = resumir_saldos([0, 100, None, 300])

Ahora llamas sin prefijo. Esta variante también carga el módulo; no evita ejecutar su inicialización. import medidas_demo as medidas usa un alias local y permite medidas.resumir_saldos(...). Elige una forma que haga clara la procedencia; evita import *, que mezcla nombres y puede ocultar los tuyos.

3. Qué ocurre al importar y por qué existe la protección de entrada

Importar ejecuta el código del nivel superior del módulo: lo que está fuera de las funciones. La instrucción def crea la función, pero no ejecuta su cuerpo. En cambio, una llamada escrita fuera de ella sí se ejecutaría:

# Ejemplo de una decisión que no queremos en un módulo reutilizable:
print("Leyendo archivos...")
# datos = pd.read_csv("cortes.csv")
# exportar(datos)

Si otro archivo importa ese módulo, aparecería el mensaje y se activarían las acciones que estuvieran descomentadas. No hace falta llamar una función desde el notebook para que suceda. Un import no es una operación de copiar texto.

En medidas_demo.py la demostración queda dentro de main():

def main():
    print(resumir_saldos([0, 100, None, 300]))

if __name__ == "__main__":
    main()

__name__ es un nombre que Python establece. Al importar este módulo, su valor es "medidas_demo"; al ejecutarlo como programa principal, es "__main__". La condición decide si llamar main(). main es un nombre convencional de función: Python no lo invoca automáticamente.

Acción __name__ de medidas_demo.py ¿Se llama su main()?
import medidas_demo medidas_demo No
python medidas_demo.py __main__ Sí
python -m medidas_demo __main__ Sí

La protección solo cubre el bloque indentado. Una lectura o una llamada a exportar escrita antes de ella sigue ocurriendo al importar. Nuestra regla concreta: importar define funciones y constantes, sin leer CSV, dibujar, imprimir resultados, analizar argumentos ni crear entregas. Python puede crear su caché técnica __pycache__; eso no es una entrega de datos.

4. Un paquete organiza varios módulos relacionados

El ejemplo pequeño cabe en un módulo. El análisis completo tiene tareas distintas. Un paquete regular permite agrupar módulos en una carpeta con __init__.py. Ese archivo inicializa el paquete; aquí solo contiene una descripción para mantener su importación sencilla. Hay otros tipos de paquetes, como los paquetes de espacio de nombres, que no necesitamos en esta sección.

01_notebook_to_modules/
├── medidas_demo.py
├── ejecutar.py
├── exploracion.ipynb
└── analisis_cartera/
    ├── __init__.py
    ├── __main__.py
    ├── reglas.py
    ├── entrada.py
    ├── transformacion.py
    ├── comprobacion.py
    ├── presentacion.py
    └── flujo.py

El módulo educativo 05 es una etapa del curso; el módulo Python entrada.py es código importable. Tampoco confundas este paquete local con una distribución instalada mediante pip: para esta práctica basta la carpeta de la lección. Publicar paquetes o añadir un sistema de construcción queda fuera del objetivo.

Desde un consumidor externo al paquete:

from analisis_cartera.entrada import read_detail
from analisis_cartera.transformacion import summarize

Es una importación absoluta: identifica paquete y módulo. Dentro de flujo.py:

from .entrada import read_detail
from .transformacion import summarize

El punto inicial indica el paquete actual, no una ruta del disco ni el directorio desde el que lanzaste Python. Es una importación relativa. Por eso no ejecutamos python analisis_cartera/flujo.py: ese archivo necesita el contexto del paquete. Importarlo o ejecutar la entrada con -m lo proporciona.

5. Separar responsabilidades sin cambiar la pregunta

La pregunta sigue siendo: ¿qué mediana de saldo conocido tiene cada segmento en octubre de 2026 y con qué cobertura? Las fuentes son los CSV de SQL 03.01, o las copias conservadas en tu entrega de 04.09.

Archivo Responsabilidad Entrada → resultado
reglas.py Orden de segmentos y campos conciliados Constantes compartidas
entrada.py Leer CSV, comprobar claves/tipos y relacionar Carpeta → detalle
transformacion.py Seleccionar corte, mediana y cobertura Detalle + fecha → dos tablas
comprobacion.py Referencia CSV/statistics y conciliación Fuentes/tablas → controles
presentacion.py Dibujar la misma tabla y redactar el informe Tablas → figuras/texto
flujo.py Coordinar y exportar cuando se pide Fuentes + destino → entrega
main.py Elegir valores iniciales y llamar al flujo Ejecución del paquete

La referencia independiente no calcula la mediana a través de summarize: usa csv y statistics como en 04.09. Si ambas rutas compartieran el mismo cálculo erróneo, la conciliación podría aceptar ese error.

flowchart TD
    A[Script o notebook] --> B[flujo]
    B --> C[entrada: leer y validar]
    C --> D[transformacion: tablas]
    B --> E[comprobacion: referencia CSV]
    D --> F[conciliar valores y ausencias]
    E --> F
    F --> G[presentacion: figuras y texto]
    G --> H[exportar a carpeta nueva si se solicita]

Sin renderizador: los dos consumidores llaman al mismo flujo. La lectura produce detalle, la transformación produce un resumen y otra ruta produce una referencia. Se concilian antes de entregar figuras. Ningún módulo de cálculo importa al script que lo ejecuta; evitamos un ciclo de dependencias.

Abre transformacion.py y sigue summarize: filtra el corte con .copy(), recorre los segmentos conocidos, calcula sobre valores no ausentes y devuelve selected, summary. La tupla devuelve dos resultados; selected, summary = summarize(detail, cut) los asigna a dos nombres. .copy() conserva el detalle recibido. En esta sección el núcleo se concentra en mediana/cobertura: no necesita calcular cuartiles ni construir pares para un explorador. Esas actividades permanecen en las lecciones previas.

Abre flujo.py. build_analysis(source, cut) lee, transforma y concilia, y devuelve un diccionario de cinco tablas; no escribe salidas. export(source, output, cut) llama ese recorrido, crea una carpeta nueva y guarda tablas, fuentes, informe, Matplotlib PNG/SVG y Altair JSON/HTML. La construcción de una Figure es una acción: se realiza al llamar, no al importar.

6. Directorio de trabajo, búsqueda de módulos y rutas de datos

Python debe encontrar la carpeta que contiene el paquete. Al ejecutar un archivo, normalmente incluye su carpeta en la búsqueda; con python -m o una sesión interactiva normal, incluye el directorio de trabajo. También busca bibliotecas del entorno elegido. No busca automáticamente en todas las subcarpetas de un repositorio.

Dos preguntas diferentes:

  • ¿Dónde encuentra Python el código? Para nuestro paquete local, en la carpeta de la lección desde la que iniciamos la sesión.
  • ¿Dónde están los datos? En una ruta que pasamos a read_detail o export. Una ruta relativa se interpreta desde el directorio de trabajo.

Path.cwd() muestra el directorio de trabajo; __file__ identifica el archivo de un módulo. En main.py, Path(__file__).resolve().parents[1] ubica la lección, con independencia del directorio de lanzamiento. resolve() obtiene una ruta absoluta y parents[1] sube dos niveles desde el archivo. Luego la entrada construye rutas conocidas dentro del repositorio. Un notebook no dispone normalmente de su propio __file__; por eso comprobamos su carpeta de trabajo de manera explícita.

En 04 se ajustaba sys.path para compartir scripts entre lecciones; se conservan esas muestras históricas. El paquete de 05.01 no hace esos ajustes, no modifica PYTHONPATH y no requiere una instalación editable. Para otra estructura de proyecto habrá que elegir cómo hacer disponible el paquete, no pegar rutas personales en cada notebook.

7. Reutilizar desde el notebook

Abre exploracion.ipynb con el kernel elegido. La primera celda muestra intérprete y carpeta y detiene la ejecución si no estás en la carpeta de la lección. Corrige el directorio de inicio del servidor/kernel o abre la lección como carpeta de trabajo; no agregues rutas a sys.path para silenciar el problema. Si necesitas iniciar Jupyter, sigue 00.06.

El notebook importa build_analysis y delivery_figure: no contiene copias de sus definiciones. Muestra tablas, revisa cifras de octubre y dibuja la misma Figure. Importa display de IPython, el entorno interactivo del kernel, para mostrarla dentro del notebook y cierra la figura que creó. No escribe otra entrega automáticamente.

Para explorar las copias de 04.09, pasa a build_analysis la carpeta fuentes de esa entrega; desde la lección, la ruta debe referirse a esa ubicación real. También puedes usar una ruta absoluta construida por ti, sin publicarla dentro del notebook. Para otra fecha cambia el argumento cut, no el código del cálculo.

Cambié un módulo, pero el notebook conserva el resultado anterior

Python normalmente conserva módulos ya importados durante la sesión. Volver a ejecutar el mismo import no garantiza cargar tus cambios del disco. Reinicia el kernel y ejecuta todas las celdas en orden. Eso elimina además las variables creadas en pruebas anteriores. Limpiar las salidas visibles no reinicia el kernel. reload es una ampliación y puede dejar referencias antiguas a funciones importadas con from; para esta práctica elegimos reiniciar.

8. Qué se conserva y cómo comprobarlo

Contrasta las tablas nuevas con estos resultados esperados. Si tienes tu entrega de 04.09, compárala también sobre las mismas fuentes y fecha. Deben coincidir por valores y ausencias, no solo por aspecto visual:

Segmento Registros Conocidos Mediana (MXN) Cobertura
comercio 5 5 3100 100 %
consumo 10 10 1750 100 %
educacion 3 0 Ausente 0 %
servicios 6 6 2550 100 %
Todos 24 21 2300 87,5 %

El saldo cero del crédito 004 sigue participando. El corte sin registros conserva los cuatro segmentos, con medianas y coberturas no definidas; un segmento con registros pero ningún saldo conocido tiene cobertura 0 %. La mediana global se obtiene del detalle conocido, no de medianas de segmentos.

Prueba además una lista vacía, todos ausentes y una mediana de medio MXN con medidas_demo. En el análisis completo compara el detalle antes/después de summarize para comprobar que no se modifica. La conciliación CSV produce 20 comparaciones; no reemplaza revisar la figura y explicar el hallazgo.

El núcleo conserva PNG/SVG Matplotlib y JSON/HTML Altair de 04.09. HTML básico necesita conexión; no migramos el explorador ni HTML incorporado en esta primera reorganización. Esas ampliaciones y sus entregas se conservan en 04.08/04.09. No se exige que imágenes tengan bytes idénticos. La carpeta nueva protege entregas anteriores; una interrupción aún puede dejar archivos parciales.

9. Errores habituales y cómo razonar sobre ellos

Síntoma Qué revisar
ModuleNotFoundError: analisis_cartera Directorio de inicio; que la carpeta padre del paquete esté disponible
ModuleNotFoundError: pandas Intérprete/kernel y dependencias del entorno elegido
attempted relative import with no known parent package Se ejecutó un archivo interno; usar el consumidor o python -m analisis_cartera
Se exporta al importar Buscar llamadas al nivel superior, también en init.py
Un cambio no aparece en el notebook Reiniciar kernel y ejecutar todo
FileExistsError El destino ya existe; usar otra carpeta mediante export, conservar la anterior
Importación circular Revisar si entrada/transformación importan flujo o la entrada principal

Evita archivos locales llamados pandas.py, statistics.py o json.py: pueden ocultar bibliotecas del entorno. print(medidas_demo.__file__) muestra la procedencia del módulo importado. Cambiar de entorno y cambiar de carpeta resuelven problemas distintos; diagnostica antes de instalar paquetes.
