Tiempo orientativo

30 a 45 minutos. No es una carrera: el objetivo es poder explicar cada resultado.

Realiza el lab en el shell que estés usando. Las instrucciones principales están expresadas por intención; consulta la tabla de equivalencias para PowerShell y Bash/Zsh.

Si aún no tienes un entorno local, puedes hacer primero el ensayo del notebook para Colab. Incluye sus propias instrucciones, carpeta temporal y CSV. Allí practicas los conceptos de ubicación, navegación e inspección de las partes A, B y E con una muestra distinta de la copia del repositorio. No busques ROADMAP.md ni pyproject.toml en esa muestra. Las partes C y D del entorno personal quedan pendientes: las herramientas de Colab corresponden a la máquina remota. Conserva tu cuaderno con respuestas y retoma la copia real en tu equipo después.

Intenta cada parte antes de abrir su solución. Los apartados desplegables muestran una forma de resolverla y explican el resultado; otras respuestas pueden ser válidas.

Recorrido esencial y diagnóstico

Para comenzar, sigue A → B → E: ubicación, navegación y lectura del CSV. Después vuelve a C para registrar herramientas disponibles o faltantes y a D si Python ya está disponible. Parte A — Ubicación

  1. Ve a la raíz de ds_track.
  2. Muestra el directorio actual.
  3. Lista los elementos visibles y ocultos.
  4. Comprueba que existen README.md, ROADMAP.md y pyproject.toml.

Preguntas:

  • ¿Qué diferencia observaste al incluir los elementos ocultos?
  • ¿Qué devuelve la comprobación de existencia cuando cambias una letra del nombre?
Ver solución de la parte A — PowerShell

Abre la terminal en la carpeta donde descargaste ds_track. Si estás en otra ubicación, usa Set-Location "RUTA_REAL_DEL_PROYECTO", sustituyendo el marcador.

# Comprueba la ubicación
Get-Location
# Lista el contenido visible y después incluye los elementos ocultos
Get-ChildItem
Get-ChildItem -Force
# Comprueba los archivos que identifican la raíz
Test-Path README.md
Test-Path ROADMAP.md
Test-Path pyproject.toml

Las tres comprobaciones devuelven True. -Force incluye elementos marcados como ocultos; la diferencia visible depende del sistema y los atributos de los archivos. Un nombre inexistente devuelve False; cambiar solo mayúsculas puede seguir encontrando el archivo en un sistema que no distingue mayúsculas y minúsculas.

Ver solución de la parte A — Bash/Zsh

Sitúate en tu carpeta del proyecto con cd "RUTA_REAL_DEL_PROYECTO".

# Comprueba la ubicación y lista los archivos
pwd
ls
# Incluye nombres que empiezan por punto y muestra detalles
ls -la
# Imprime un mensaje si cada archivo existe
test -e README.md && echo "existe"
test -e ROADMAP.md && echo "existe"
test -e pyproject.toml && echo "existe"

Los archivos ocultos suelen comenzar por punto. Si la ruta no existe, test -e falla y no se imprime el mensaje; no muestra False.

Pregunta:

  • Si estás en curriculum/00_getting_started, ¿qué representa subir dos veces a la carpeta padre (../.. o ..\..)?
Ver solución de la parte B — PowerShell

Desde la raíz:

# Entra al módulo

# Lista su contenido
Get-ChildItem
# Sube al directorio curriculum y después a ds_track

Cada .. representa una carpeta padre. Subir dos veces desde el módulo te lleva a la raíz de ds_track; no significa ir siempre a la raíz de la unidad.

# Sube dos carpetas y confirma la ubicación

pwd

La primera subida llega a curriculum y la segunda a ds_track.

Parte E — Inspección de datos

  1. Desde la raíz, localiza ventas_demo.csv dentro de la carpeta de la lección.
  2. Comprueba que existe y muestra sus primeras tres líneas.
  3. Identifica las columnas y explica cuántos registros viste, sin contar el encabezado.
  4. Explica una tarea de datos que podrías repetir mediante un comando y qué necesitaría otra persona para ejecutarlo en su computadora.
Ver solución de la parte E — PowerShell 
# Lista CSV de la lección
Get-ChildItem curriculum\00_getting_started\02_terminal_paths -Filter *.csv
# Guarda la ruta de la muestra
$ventasPath = "curriculum\00_getting_started\02_terminal_paths\ventas_demo.csv"
# Confirma la existencia y muestra tres líneas
Test-Path $ventasPath
Get-Content $ventasPath -TotalCount 3

Las columnas son fecha, producto, unidades e importe_mxn. Ves el encabezado y dos registros; el archivo completo contiene tres registros. Una tarea repetible sería generar un resumen mensual. Otra persona necesitaría el programa, los datos, las dependencias y saber desde dónde ejecutarlo.

Ver solución de la parte E — Bash/Zsh 
# Lista CSV y guarda la ruta

ventas_path="curriculum/00_getting_started/02_terminal_paths/ventas_demo.csv"

La primera línea contiene los cuatro nombres de columnas y las siguientes dos son registros. El encabezado no es una venta. Para repetir un análisis, comparte también sus entradas e instrucciones de ejecución.

Extensión opcional — Explorar el CSV

Después de leer la sección 8 de la lección:

  1. Cuenta las líneas y compara el resultado con la cantidad de registros.
  2. Filtra las ventas de lapiz y comprueba el resultado en el archivo.
  3. Filtra los importes de al menos 50 MXN y explica qué registros permanecen.
  4. Calcula el importe total y compruébalo sumando los tres valores manualmente.
  5. Prueba el reto de unidades y explica qué aporta combinar comandos.

Esta extensión no bloquea el avance. En PowerShell, compara los números convirtiendo los campos de texto; en Bash/Zsh, aplica los ejemplos solo a la muestra sencilla y explica su limitación para CSV más complejos.

Ver solución de la extensión — PowerShell

Desde la raíz:

# Lee líneas de texto y cuenta: 4
$ventasPath = "curriculum\00_getting_started\02_terminal_paths\ventas_demo.csv"
Get-Content $ventasPath | Measure-Object -Line
# Importa registros y cuenta sin encabezado: 3
$ventas = @(Import-Csv $ventasPath)
$ventas.Count
# Filtra el producto: una venta, 5 unidades, 50 MXN
$ventas | Where-Object { $_.producto -eq "lapiz" }
# Filtra importes: cuaderno (80) y lapiz (50)
$ventas | Where-Object { [decimal]$_.importe_mxn -ge 50 }
# Suma importes: 165
($ventas | ForEach-Object { [decimal]$_.importe_mxn } | Measure-Object -Sum).Sum
# Reto: al menos dos unidades; quedan cuaderno y lapiz
$ventas | Where-Object { [int]$_.unidades -ge 2 }

La comprobación manual es 80 + 50 + 35 = 165. Los campos del CSV son texto, por eso se convierten antes de comparar números o sumar. Cada comando cumple una tarea y los pipes permiten combinar lectura, filtro y resumen.

Ver solución de la extensión — Bash/Zsh 
ventas_path="curriculum/00_getting_started/02_terminal_paths/ventas_demo.csv"
# Cuenta saltos de línea: 4
wc -l < "$ventas_path"
# Cuenta registros de esta muestra sencilla: 3
awk 'NR > 1 { cantidad++ } END { print cantidad }' "$ventas_path"
# Busca la venta de lapiz
grep ',lapiz,' "$ventas_path"
# Muestra cuaderno 80 y lapiz 50
awk -F',' 'NR > 1 && $4 >= 50 { print $2, $4 }' "$ventas_path"
# Suma importes: 165
awk -F',' 'NR > 1 { total += $4 } END { print total }' "$ventas_path"
# Reto de unidades: cuaderno y lapiz
awk -F',' 'NR > 1 && $3 >= 2 { print $2, $3 }' "$ventas_path"

La suma manual es 80 + 50 + 35 = 165. Estas herramientas procesan texto: separar por comas funciona aquí, pero no interpreta CSV con comas dentro de campos entre comillas o registros de varias líneas.
