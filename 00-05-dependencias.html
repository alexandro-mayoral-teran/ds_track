1. Instalar e importar

En 05A preparaste un entorno y ejecutaste el primer script, que no requería bibliotecas externas. Ahora queremos presentar tres ventas como una tabla: cuaderno 80, lapiz 50 y carpeta 35 MXN. Para hacerlo utilizaremos tabulate 0.9.0. El motivo y las acciones son los mismos con cualquiera de los tres gestores.

Instalar y utilizar son dos pasos diferentes

  1. Instalar el paquete: el gestor descarga sus archivos y los coloca en el entorno elegido. Por ejemplo, instalar tabulate deja esa biblioteca disponible para el Python de ese entorno.
  2. Importar en el programa: el código indica qué funcionalidad quiere utilizar. En nuestro ejemplo, from tabulate import tabulate permite usar la función que presenta los datos como una tabla.

Instalar una biblioteca no la añade automáticamente a todos tus programas. Importarla tampoco la descarga: si no está disponible para el intérprete que ejecuta el código, Python informará que no encuentra el módulo.

Dos nombres que conviene distinguir

  • Nombre de instalación: identifica el paquete que solicitas al gestor.
  • Nombre de importación: identifica el módulo que utilizas en el código.

En esta práctica ambos son tabulate. En otras bibliotecas pueden ser distintos; consulta sus instrucciones de instalación y uso en lugar de asumir que coinciden.

Qué papel tiene el editor

VS Code te permite escribir el programa. Abrir un archivo o instalar una extensión del editor no instala automáticamente las bibliotecas que el programa necesita. Esas bibliotecas deben estar disponibles en el entorno del Python que lo ejecuta.

Predecir y comprobar con la demostración

Antes de ejecutar library_demo.py, abre el archivo y localiza from tabulate import tabulate. Esa línea pide la función de la biblioteca; no la instala. No necesitas dominar todavía las estructuras del resto del script.

Predice qué ocurriría si el intérprete elegido no tuviera tabulate disponible. Después instala y ejecuta siguiendo la parte B de tu recorrido. Debes obtener:

| Producto   |   Importe MXN |
|------------|---------------|
| cuaderno   |            80 |
| lapiz      |            50 |
| carpeta    |            35 |

Si aparece ModuleNotFoundError: No module named 'tabulate', el Python que ejecutó el archivo no encontró ese módulo. Comprueba la ruta del intérprete y la instalación de ese entorno con los comandos de tu recorrido antes de intentar instalar otra vez. No hace falta desinstalar nada para provocar el error.

2. Qué contiene requirements.txt y cómo se utiliza

Lee el formato de tu camino; los otros quedan como consulta. Todos cumplen la necesidad de conservar requisitos presentada en 05A, con alcances distintos. Los siguientes ejemplos explican archivos y comandos; guarda la configuración en la ubicación que indica tu recorrido, sin modificar los archivos raíz de DS Track.

requirements.txt es un archivo de texto con una lista de cosas que pip debe instalar. Puedes escribir los requisitos que necesita el proyecto, por ejemplo:

# Biblioteca utilizada en la demostración
tabulate==0.9.0

==0.9.0 pide esa versión exacta. También existen requisitos sin una versión fijada o con rangos, pero aquí usamos una versión concreta para comparar resultados. El nombre requirements.txt es convencional; no es una palabra reservada de Python.

Desde la carpeta que contiene el archivo y utilizando el Python del entorno:

# Instala lo declarado en el archivo
python -m pip install -r requirements.txt

-r indica que pip debe leer los requisitos del archivo. No crea un entorno ni instala Python: primero prepara y selecciona el intérprete de 05A. Si no activaste el entorno, usa la ruta directa de su Python como en el recorrido pip.

Escribir requisitos o capturar lo instalado

Son dos operaciones distintas:

  • Escribir el archivo: declaras los paquetes que quieres instalar para el proyecto.
  • Generarlo con freeze: registras las versiones de lo que está instalado en el entorno, incluidas sus dependencias transitivas.
# Captura el estado instalado en una lista de requisitos
python -m pip freeze > requirements.txt

> escribe en el archivo y puede sobrescribirlo. Revisa la ubicación antes de usarlo. En PowerShell sigue el método con Set-Content del recorrido pip para escribir texto UTF-8. Exporta desde un entorno del proyecto, no desde una instalación con paquetes de muchos trabajos distintos.

freeze no analiza cuáles paquetes usa tu código ni genera por sí solo un lockfile. Aunque fijes versiones, pueden existir limitaciones de plataforma o requisitos externos. Documenta también Python y comprueba la reconstrucción.

3. Archivos de cada recorrido

Conda: environment.yml

Describe el nombre del entorno, los canales y sus dependencias. Ejemplo para leer:

name: ds-track
channels:
  - conda-forge
dependencies:
  - python=3.12
  - pip
  - tabulate=0.9.0

La exportación desde historial recoge elecciones hechas con Conda, sin fijar necesariamente todas las dependencias transitivas ni incluir paquetes instalados con pip. Si utilizas ambas fuentes, debes declararlas. El archivo permite crear el entorno; no es una carpeta de paquetes ni un lockfile exacto.

uv: pyproject.toml y uv.lock

pyproject.toml declara información del proyecto y requisitos. TOML es el formato del archivo, no una herramienta exclusiva de uv. Ejemplo de un fragmento:

[project]
name = "uv-demo"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = ["tabulate==0.9.0"]

uv.lock conserva la resolución de dependencias que produjo uv. No lo escribas manualmente para esta práctica: uv add o uv lock lo generan. uv sync –locked prepara el entorno y comprueba que el lockfile corresponda a la configuración. Los dos archivos cumplen funciones distintas y se comparten junto con el código.

Archivo Qué expresa Qué no hace por sí solo
requirements.txt Requisitos de instalación para pip Crear el entorno o instalar Python
environment.yml Especificación de un entorno Conda Garantizar toda la resolución exacta entre plataformas
pyproject.toml Metadatos y requisitos del proyecto Python Contener una copia de los paquetes
uv.lock Resolución de dependencias de uv Sustituir el código, los datos o todos los requisitos del sistema

4. Reconstruir en vez de copiar el entorno

La secuencia es compartir código y configuración → preparar un entorno → instalar lo declarado → ejecutar y comprobar. No copies .venv entre computadoras.

  • pip: crea el entorno primero e instala el archivo con -m pip install -r.
  • Conda: crea el entorno desde el YAML, como indica su recorrido.
  • uv: utiliza la configuración y el lockfile con uv sync --locked.

Revisa los archivos antes de compartir: evita rutas personales, credenciales y paquetes ajenos al proyecto. Los archivos de práctica están en carpetas locales ignoradas; conserva una copia revisada si necesitas presentar la evidencia.
