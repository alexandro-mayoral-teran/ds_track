Propósito

Representar datos relacionados y sus operaciones cuando una estructura propia ayude a entender el programa. Aprenderemos a leer y crear objetos pequeños; también a justificar cuándo una función o un diccionario bastan.

Antes de empezar

Base de esta ampliación: clase, instancia, atributos, métodos y self. Práctica: estado propio/compartido, dataclass, validación y composición. Extensión: fábricas de valores y límites de frozen. 1. Elegir una representación antes de escribir class

Queremos calcular la cobertura de dos conocidos sobre tres registros. Ya tenemos la función comprobada coverage_pct:

from analisis_cartera.contratos import coverage_pct

print(coverage_pct(2, 3))
counts = {"known": 2, "total": 3}
print(coverage_pct(counts["known"], counts["total"]))

Ambas llamadas producen aproximadamente 66,6667 %. La función basta para una operación aislada. El diccionario reúne datos con claves; puede ser útil para una estructura flexible o una entrada leída desde JSON. Debemos comprobar sus claves y valores: escribir counts["knwon"] provoca KeyError.

Una clase puede reunir datos con operaciones que tienen sentido para ese tipo de objeto. Añade nombres y responsabilidades, pero también código que hay que entender y mantener. No vuelve más correcto un cálculo por el hecho de usarla.

Necesidad Elección razonable Pregunta para justificarla
Calcular una cobertura aislada Función ¿Necesito conservar un objeto después?
Recibir un objeto JSON con claves variables Diccionario y validación ¿Las claves pueden variar entre entradas?
Conservar opciones con campos estables dataclass ¿Los campos forman un concepto que reutilizo?
Reunir estado y operaciones relacionadas Clase pequeña ¿Se entiende qué representa y de qué es responsable?
Transformar miles de filas tabulares Funciones de pandas ya conocidas ¿Aporta algo envolver cada fila o tabla?

En este material los DataFrames siguen siendo tablas. Los objetos nuevos representan conteos y opciones de revisión, no un reemplazo de pandas.

2. Una clase manual pequeña

Abre objetos.py. La primera clase del archivo contiene este comportamiento:

class CoverageCounts:
    def __init__(self, known: int, total: int) -> None:
        coverage_pct(known, total)
        self.known = known
        self.total = total

    def percentage(self) -> float | None:
        return coverage_pct(self.known, self.total)

class CoverageCounts: define un tipo propio. La indentación indica qué funciones pertenecen a esa clase. El nombre describe conteos de cobertura. Definir la clase no crea todavía una pareja concreta de conteos.

from analisis_cartera.objetos import CoverageCounts

counts = CoverageCounts(2, 3)
print(counts.known)          # 2
print(counts.total)          # 3
print(counts.percentage())   # aproximadamente 66,6667

CoverageCounts(2, 3) crea una instancia. Python prepara un nuevo objeto y llama a su inicializador __init__; no necesitamos estudiar new aquí. __init__ recibe los argumentos, comprueba los conteos con la función de 05.05 y establece atributos en esa instancia. Debe devolver None; no devuelvas self.

Un atributo es un dato accesible mediante el punto, como counts.known. Un método es una operación vinculada al objeto, como counts.percentage(). El punto permite encontrar el nombre; los paréntesis ejecutan la operación. Un nombre mal escrito también puede producir un error en una clase, por ejemplo AttributeError. La ventaja es reunir un concepto y su interfaz, no eliminar la necesidad de revisar nombres, tipos y reglas.

3. self, parámetros y atributos no son el mismo nombre

En self.known = known, el nombre de la derecha es el parámetro de esta llamada; el de la izquierda queda guardado en el objeto. self representa la instancia actual. Es una convención de nombre que seguimos de forma uniforme.

Al llamar counts.percentage(), Python proporciona counts como self. Para esta clase, también podríamos escribir CoverageCounts.percentage(counts); la forma con el objeto y el punto es la habitual. No debes pasar counts dos veces.

first = CoverageCounts(2, 3)
second = CoverageCounts(0, 3)
print(first.percentage())    # aproximadamente 66,6667
print(second.percentage())   # 0.0

Es la misma receta con dos estados distintos. La clase no contiene “el último conteo usado”; cada instancia guarda sus propios atributos porque asignamos self.known y self.total dentro del inicializador.

Ahora puedes releer las pruebas de 05.04: la clase hereda de unittest.TestCase, sus métodos reciben self y setUp prepara atributos para cada caso. Allí usamos la interfaz de un framework; aquí estamos diseñando un objeto del problema.

4. Estado mutable, alias y resultados que se vuelven obsoletos

Los atributos de CoverageCounts son públicos y pueden reasignarse:

first = CoverageCounts(2, 3)
alias = first
second = CoverageCounts(2, 3)
alias.known = 1
print(first.known)       # 1: alias y first nombran el mismo objeto
print(second.known)      # 2: second es otra instancia

Asignar alias = first no copia el objeto. Cambiarlo mediante cualquiera de esos nombres se observa desde el otro. first is alias pregunta por identidad; == compara según la regla de igualdad del tipo. Para esta clase manual no definimos igualdad por campos: dos instancias distintas conservan la comparación por identidad que heredan de object. No uses == como sustituto universal de is.

Validar solo al construir tampoco protege todos los cambios posteriores: alias.known = 4 deja el estado fuera de 0 <= known <= total. El método percentage vuelve a llamar coverage_pct y rechaza ese estado con ValueError. La instancia mutable no garantiza ser válida en todo momento.

No almacenamos además un atributo percentage_result: cambiar known dejaría ese resultado desactualizado si nadie lo recalcula. El método deriva el porcentaje desde el estado actual. La función sigue siendo la responsable de la regla.

5. Atributos de clase y de instancia: cuidado con las listas compartidas

Este ejemplo independiente muestra un error frecuente:

class SharedNotes:
    notes = []

a = SharedNotes()
b = SharedNotes()
a.notes.append("revisar base")
print(b.notes)  # ['revisar base']

notes se creó en el cuerpo de la clase. Como ninguna instancia tiene todavía un atributo propio de ese nombre, ambas encuentran la misma lista de la clase. append modifica esa lista; no crea una lista distinta para a.

Para notas propias por instancia, créalas al inicializar:

class OwnNotes:
    def __init__(self) -> None:
        self.notes = []

a = OwnNotes()
b = OwnNotes()
a.notes.append("revisar base")
print(b.notes)  # []

Los dos ejemplos se pueden ejecutar por separado. Un atributo de clase puede ser apropiado para información compartida intencionalmente; una lista de trabajo individual debe pertenecer a la instancia. Nombres con un guion bajo inicial indican uso interno por convención, pero no hacen al dato inaccesible ni inmutable.

6. Cuando el trabajo repetido son los campos: dataclass

Ahora queremos conservar opciones con nombres estables: corte y segmentos. Podemos escribir a mano el inicializador, la representación y la igualdad. La biblioteca estándar ofrece dataclass para generar parte de ese trabajo.

Ejemplo introductorio, deliberadamente sin validación:

from dataclasses import dataclass

@dataclass
class SimpleOptions:
    cut: str = "2026-10-31"

first = SimpleOptions()
second = SimpleOptions(cut="2026-10-31")
print(first)              # SimpleOptions(cut='2026-10-31')
print(first == second)    # True: compara sus campos
print(first is second)    # False: son dos objetos

@dataclass usa un decorador existente: recibe la clase y agrega comportamiento según sus campos. Aprender a crear decoradores propios pertenece a 05.08 y no es requisito para usar este. En la configuración habitual se generan init, repr y eq, entre otros detalles; no necesitas escribir esos métodos ahora. repr produce una representación útil para inspeccionar; eq define ==.

Las anotaciones identifican campos, pero no validan sus valores. En el ejemplo, SimpleOptions(cut=31) se construye aunque incumpla str. La lección de contratos sigue vigente: la validación se programa explícitamente. Una dataclass es una clase con ayuda para representar datos, no un lector de CSV ni un esquema tabular.

7. ReviewOptions: campos con reglas explícitas

La dataclass real del paquete empieza así; consulta el archivo para ver el cuerpo de validación completo:

@dataclass(frozen=True)
class ReviewOptions:
    cut: str = DEFAULT_CUT
    segments: tuple[str, ...] | None = None

DEFAULT_CUT es la constante “2026-10-31” ya conocida. tuple[str, ...] describe una tupla de longitud variable con elementos de texto; no es la tupla de dos tablas con posiciones fijas que devuelve summarize. Una tupla de un elemento se escribe ("comercio",) con coma. () es la tupla vacía.

Campo Regla
cut Texto con fecha válida YYYY-MM-DD; predeterminado fijo, no fecha actual
segments=None Todos los grupos
segments=() Ningún grupo, conservando lectura y validación
Tupla explícita Nombres únicos del catálogo, en el orden solicitado

La clase define __post_init__(self) -> None. El init generado establece los campos y después llama ese método; allí comprobamos tipos, fecha, catálogo y duplicados. No lo llamas manualmente para que una instancia recién creada sea válida. No definimos un init propio en estas dataclasses.

from analisis_cartera.objetos import ReviewOptions

options = ReviewOptions(segments=("educacion", "comercio"))
print(options.cut)       # 2026-10-31
print(options.segments)  # ('educacion', 'comercio')

Aquí cut=None y segments=[“comercio”] se rechazan con TypeError. Es una interfaz de configuración que exige corte explícito como texto y selección inmutable como tupla. La función review_summary de 05.05 conserva su interfaz anterior, que sí admite cut=None y selección como lista. El objeto adaptará su tupla a esa lista al delegar; no cambiamos los consumidores anteriores.

8. frozen, replace y el contenido de los campos

Con frozen=True, una asignación normal como options.cut = "2026-09-30" lanza FrozenInstanceError. Para preparar una variación sin alterar la configuración anterior, usamos replace:

from dataclasses import replace

original = ReviewOptions(segments=("comercio",))
september = replace(original, cut="2026-09-30")
print(original.cut)    # 2026-10-31
print(september.cut)   # 2026-09-30

replace construye otra instancia y vuelve a pasar por post_init. Una fecha o selección inválida también se rechaza en esa nueva construcción. No es una modificación silenciosa del original ni una copia recursiva de todo objeto contenido. Los campos no cambiados se reutilizan.

frozen limita la reasignación de atributos; no congela automáticamente una lista guardada en ellos. Este ejemplo muestra ese límite y una fábrica de valores:

from dataclasses import dataclass, field

@dataclass(frozen=True)
class Notes:
    labels: list[str] = field(default_factory=list)

a = Notes()
b = Notes()
a.labels.append("revisar")
print(a.labels)  # ['revisar']: se modificó la lista interior
print(b.labels)  # []: cada instancia recibió su propia lista

field(default_factory=list) pide crear una lista cuando se necesite el valor predeterminado. Se pasa list sin paréntesis para que se llame entonces. No uses labels: list[str] = []: dataclasses rechaza ese predeterminado mutable. La fábrica evita compartirlo; no vuelve inmutable a la lista.

ReviewOptions combina frozen con campos de texto, None o tuplas de textos validados. No guarda listas ni DataFrames. Esto permite reutilizar opciones sin que una selección exterior cambie por append. No generalices esa propiedad a una dataclass que contenga otros objetos mutables.

9. Composición: una solicitud contiene sus opciones

ReviewJob representa una revisión que se puede ejecutar. Contiene una fuente y una instancia de ReviewOptions. Esa relación se llama composición:

flowchart LR
    J[ReviewJob] -->|contiene| O[ReviewOptions]
    J -->|summary delega| F[review_summary de 05.05]
    O -->|corte y segmentos| F
    F -->|lee y concilia| C[CSV de entrada]
    F -->|devuelve| T[Resumen DataFrame]

Sin renderizador: una solicitud guarda ruta/opciones; al pedir summary, entrega esos parámetros a la función ya comprobada. La función lee y concilia antes de devolver la tabla. La solicitud no guarda las filas ni una conexión abierta.

En objetos.py, ReviewJob usa otra dataclass con frozen y estos campos:

source: str | Path
options: ReviewOptions = field(default_factory=ReviewOptions)

La fuente es obligatoria. La fábrica crea opciones por defecto cuando no se proporcionan. Si pasas options, el trabajo conserva esa referencia; no duplica automáticamente el objeto. Compartir estas opciones validadas de solo lectura es intencional. No hay listas de trabajo ocultas entre solicitudes.

Su método summary convierte la tupla en lista y llama review_summary. Conserva el significado de None frente a tupla vacía. En particular, no usa segments or None, que confundiría () con pedir todos los grupos.

ReviewJob contiene ReviewOptions; no necesita heredar de ella. La herencia define un tipo a partir de otro y resulta útil en interfaces como TestCase; una fuente de datos y sus opciones no requieren esa relación. Para esta necesidad basta composición con funciones existentes.

10. Construir un objeto no ejecuta el análisis

from pathlib import Path
from analisis_cartera.objetos import ReviewJob, ReviewOptions

source = Path("../../03_sql_databases/01_relational_sqlite/data")
job = ReviewJob(source, ReviewOptions(segments=("educacion", "comercio")))
summary = job.summary()

Este ejemplo supone una sesión en 01_notebook_to_modules. La construcción comprueba la forma de ruta/opciones, sin abrir CSV ni crear carpetas. summary() ejecuta la lectura y la conciliación, y puede lanzar los errores de la función de 05.05. Una ruta puede dejar de existir o sus archivos cambiar después de construir job; la validación de datos ocurre al usarlos.

Las rutas relativas se interpretan desde el directorio de trabajo al ejecutar summary, como en la función anterior. Si necesitas conservar una referencia absoluta al crear el trabajo, prepara antes source.resolve() de forma explícita. No prometemos que frozen conserve el contenido de los archivos externos.

Cada llamada relee y devuelve una tabla nueva: job no es una caché. Cambiar la tabla recibida no cambia las opciones ni el resultado de la próxima lectura de una fuente intacta. La selección de segmentos conserva medianas/cobertura de cada grupo; no recalcula un total global a partir de lo mostrado.

La clase organiza una solicitud reutilizable; la función mantiene el cálculo. Cuando solo necesitas una revisión, llamar review_summary directamente sigue siendo una opción clara. Para aprender esta alternativa no reescribimos CLI, notebook, lectores ni exportadores anteriores.
